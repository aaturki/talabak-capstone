# بوابة النماذج: التشغيل المحلي وحدود الأدلة

## النتيجة المؤكدة

يعمل المشروع عبر **OpenAI Python SDK** وطلب HTTP فعلي إلى خدمة محلية. هذه الخدمة
**محاكي حتمي خاص بالمسار D**؛ لا توجد أوزان نموذج تعمل خلفها، ولا اتصال بمزود مدفوع،
ولا حاجة لمفتاح شخصي. اسم SDK يصف عقد الاتصال، ولا يعني تشغيل نموذج من OpenAI.

تم جلب صفحتي [الإعداد](https://mohammadyusif.github.io/llm-application-engineering/setup.html)
و[مرجع البوابة](https://mohammadyusif.github.io/llm-application-engineering/reference/gateway.html)
بنجاح HTTP 200 في 15 سبتمبر 2026. تنصان على التشغيل الافتراضي بمحاكي دون مفتاح أو GPU.
ذكر بوابة صفية منفصلة لا يثبت عنوانها أو إتاحتها؛ لم يتم الاتصال بها.

## المحاكي الأصلي والإضافة المحلية

المصدر المقروء والمختبر هو [مستودع المقرر، commit de2ff3c](https://github.com/MohammadYusif/llm-application-engineering/tree/de2ff3c0d8758c77d85c944e2d6f133647b84a91)،
وبالأخص `murshid/infra/mockgw/app/{main,brain}.py` و`src/murshid/llm/{openai_compat,resilient}.py`.

شُغّل **الكود الأصلي دون تعديل** على منفذ loopback مؤقت. أرسل إليه SDK ثلاثة طلبات:

1. نجح عقد الأداة الأصلية `check_application_status`.
2. لم يصدر استدعاء أداة البيع بالتجزئة `lookup_order`.
3. لم يُرجع مخطط `DomainRequest` الخاص بمشروعنا.

الردود الكاملة وبصمات ملفات المصدر محفوظة في [STOCK_GATEWAY_PROBE.json](STOCK_GATEWAY_PROBE.json).
لذلك لم نعامل محاكي الخدمات الحكومية بوصفه منفذًا جاهزًا لتطبيق المتجر.

`talabak/mock_gateway.py` إضافة مكتوبة للمشروع، مستلهمة من عقد البوابة في المقرر:
استخراج حتمي عربي/إنجليزي، استدعاءات أدوات مترابطة، رد JSON من نتائج الأدوات،
تخزين بادئة ثابتة، وفشل HTTP قابل للحقن. لا يستورد بيانات التقييم أو قاعدة بيانات المتجر.
كل معلومة في الرد النهائي تأتي من `message` و`sources` في نتيجة أداة ذات معرّف مترابط.
لا تُنسخ قواعد الجودة أو النتائج من مشاريع الطلاب.

يعمل `JudgeVerdict` كتجربة لعقد الحكم فقط: تطابق نص الإجابة حرفيًا مع نص في الدليل
يعطي PASS، ووجود أرقام لا تظهر في الدليل يعطي FAIL، والتداخل اللفظي وحده يعطي PARTIAL.
كل سبب يبدأ بـ`simulator_contract`. هذه قواعد سطحية معلنة، ولا تثبت جودة الحكم أو
المعايرة البشرية. مدخلاتها مقصورة على السؤال والدليل الموثوق والإجابة المرشحة.

ملف `prompts/router.degraded.v0.md` عطل انحدار مقصود: عنوانه الثابت في رسالة النظام
يجعل المحاكي يصنف الطلبات FAQ. يستخدمه التشغيل المقارن لاختبار بوابة التراجع على
البيانات نفسها. ليس المسار الافتراضي ولا قياسًا لتأثر نموذج حي بتغيير prompt.

الإضافة الحالية تدعم **OpenAI-compatible chat/completions فقط**. لا ندّعي تنفيذ
Anthropic أو streaming أو قياس TTFT في هذه الإضافة؛ هذه مزايا في محاكي المقرر الأصلي.
جميع أسماء المسارات `primary`, `fallback`, `judge`, `open_weight` تشير إلى قواعد محلية؛
وجود اسم `open_weight` لا يثبت تشغيل نموذج مفتوح الأوزان أو إجراء مقارنة نماذج.

## التشغيل

من جذر المشروع بعد تثبيت متطلباته:

```console
python -m uvicorn talabak.mock_gateway:app --host 127.0.0.1 --port 8080
python -m pytest tests/test_llm.py -q
```

للبرنامج أو الدفتر الذي يحتاج منفذًا خاليًا تلقائيًا:

```python
import json
from talabak.llm import SDKClient, DEFAULT_CONFIG
from talabak.mock_gateway import running_gateway

with running_gateway(port=0) as base_url:
    config = json.loads(DEFAULT_CONFIG.read_text(encoding="utf-8"))
    for route in config["routes"].values():
        route["base_url"] = base_url
    with SDKClient(config=config) as model:
        # Pass the ModelClient to the application here.
        pass
```

تُغلق الخدمة عند الخروج من السياق. لا تنشئ نافذة أو عملية خارجية. الإعداد الافتراضي
في `config/models.json`؛ لا يقرأ العميل `OPENAI_API_KEY` أو `OPENAI_BASE_URL` ولا
يستخدم إعدادات proxy البيئية. يرفض عناوين الشبكات الخارجية وبيانات الاعتماد داخل URL.
النقل إلى مزود حي يحتاج عمل إعداد منفصل وتفويض المستخدم؛ هذا البناء يقبل المحاكي فقط.

## المخرجات والأدوات والاعتمادية

- تعتمد طبقة التطبيق على `ModelClient` Protocol، لا على كائنات SDK.
- يرسل العميل `response_format.type=json_schema` و`strict=true` والمخطط كاملاً.
- أدوات المشروع تحمل JSON Schema صارمًا؛ يفك العميل وسيطات الأدوات إلى object ويحفظ `id`.
- يُرفض الرد المقطوع `finish_reason=length` ويُحفظ استهلاكه في خطأ التشغيل.
- محاولات SDK الداخلية معطلة. سياستنا: محاولتان لكل مسار، تأخير أسي مع jitter،
  احترام `Retry-After` ضمن سقف ثانيتين، ثم مسار احتياطي معلن.
- تعاد محاولة أخطاء الاتصال و408/409/425/429/500/502/503/504/529.
  أخطاء 400/401/403/404 لا يعاد إرسالها ولا تحول لمسار آخر.
- تُعاد أخطاء JSON للمحتوى إلى طبقة التطبيق لتطبق إصلاح المخطط المحدود؛ العميل
  لا يختلق مخططًا صالحًا بدل الرد المعطوب.

## التوكنات والتخزين والتكلفة

يستخدم المحاكي tokenizer `o200k_base` لحساب توكنات تمثيله النصي المحدد للرسائل
والأدوات والمخطط. هذه أعداد فعلية لذلك التمثيل في المحاكي، **وليست تقديرًا موثقًا لفاتورة
مزود أو لقالب محادثة نموذج حي**. بادئة التخزين تشمل رسالة النظام والأدوات والمخطط؛
رسائل المستخدم والسياق المتغير خارجها. الحد الأدنى 1024 توكن؛ TTL يساوي 300 ثانية
ويتجدد عند الإصابة. تختلف مفاتيح التخزين بحسب النموذج وبصمة البادئة.

تعيد `usage` الحقول: `input_tokens`, `output_tokens`, `cached_tokens`, `attempts`,
`fallback_used`, `alias`, `finish_reason`, `latency_ms`. الزمن مقاس فعليًا للطلب المحلي
بما فيه الانتظار وإعادة المحاولة، ولا يثبت زمن استدلال أو إنتاجية نموذج حي.

`cost_usd=0` يعبر عن الإنفاق الفعلي على API في هذا الوضع. `simulated_cost_usd` حساب
منفصل باستخدام تعريفات افتراضية واضحة في الإعداد، مع فصل توكنات الإدخال المخزنة وغير
المخزنة. التعريفات **افتراضات تعليمية** وليست أسعار مزودين. لا تُجمع المحاولات الفاشلة
بافتراض استهلاك مجهول؛ المحاكي يحقن فشل HTTP قبل توليد الرد واستهلاكه.

ملف مفردات tokenizer مضمن في `config/tokenizer_cache` لتجنب تنزيله عند أول تشغيل.
مصدره [ملف OpenAI الرسمي](https://openaipublic.blob.core.windows.net/encodings/o200k_base.tiktoken)،
وطريقة استخدامه من [tiktoken](https://github.com/openai/tiktoken). بصمة SHA-256 المطابقة
لما يطلبه tiktoken:

```text
446a9538cb6c348e3516120d7c08b09f57c36495e2acfffe59a5bf8b0cfb1a2d
```

## فحص الخدمة وحقن الأعطال

| المسار | الوظيفة |
|---|---|
| `GET /healthz` | يعلن `implementation=talabak-track-d-extension` و`evidence_mode=simulator` |
| `GET /v1/models` | أسماء المسارات المحلية |
| `POST /v1/chat/completions` | SDK/JSON Schema/tool-call contract |
| `GET /admin/stats` | الطلبات والتوكنات وإصابات التخزين والأعطال |
| `POST /admin/reset` | تصفير عدادات المحاكي والتخزين والأعطال |
| `POST /admin/fault` | عطل محدد بالنموذج والمدة/عدد الطلبات |

مثال طلب حقن: `{"mode":"overload","model":"talabak-course-primary","seconds":60}`.
الأوضاع: `rate_limit` (429)، `overload` (529)، `server_error` (503)، `timeout` (504)،
`invalid_json`، `invalid_tool`، `tool_loop`، و`off`.
`timeout` هنا **رد 504 محقون فوري**، لا ادعاء بانتظار مهلة شبكة؛ خطأ الاتصال نفسه
مختبر بصورة منفصلة بنقل httpx محكوم.

## دليل الاختبار وحدوده

مرّت 38 حالة في `tests/test_llm.py` عند أول تشغيل بتاريخ 15 سبتمبر 2026، في 4.59 ثانية.
تشمل اتصال HTTP محليًا فعليًا، واستخراجًا عربيًا/إنجليزيًا، وربط نتائج الأدوات، وقياس
التخزين وإبطاله بانتهاء المدة أو تغيير البادئة أو النموذج، وإعادة المحاولة والتحول الاحتياطي،
ورفض المخرجات المقطوعة والوسيطات المعطوبة. يعاد توليد العدد والزمن عند التشغيل؛ هذه
لقطة اختبار وليست وعدًا ثابتًا بالأداء.

لا تثبت هذه الحالات جودة فهم نموذج حقيقي، أو حكمًا بشريًا مستقلًا، أو مقارنة بين
نماذج تجارية ومفتوحة الأوزان، أو قياس GPU/throughput. تحتاج تلك البنود أدلة مستقلة.

بعد توسيع المراجعة، مرّت **104 حالات** في مجموعة الملفات
`test_llm.py` (46)، و`test_safety.py` (43)، و`test_api.py` (15)، في 10.05 ثانية
بتاريخ 15 سبتمبر 2026. تشمل المجموعة الآن HTTP الواجهة والجلسات ورفض تزييف الصلاحيات
والتأكيد وإعادة التشغيل والتنافس على آخر قطعة أو موعد، والحماية من تسرب بيانات
المخرجات والسجل، وفحص أن استهلاك كل توليد يصل إلى نتيجة التطبيق حتى عند فشل فك JSON
أو قطع الرد. يطابق مجموع `usage.attempts` عدد أحداث محاولات HTTP عبر مجموعة التطوير
كاملة مع عطل 429 محقون. تقرير runner النهائي هو المرجع لأحدث العدد والوقت.

وجدت المراجعة أربع ثغرات في دورة حياة الطلب وأصلحت باختبارات انحدار: بقاء تأكيد
بعد رفض نتيجة أداة، وتسرب PII يولده النموذج إلى السجل، وعدم فحص مراجع FAQ،
وتسجيل رسالة exception خاصة. كما كشف فحص HTTP عدم ربط نموذج جسم JSON داخل دالة
FastAPI وعولج، وأضيف رفض Host خارجي مع Origin مطابق لمقاومة إعادة ربط DNS.
